# Design Patterns: Introduction

## What is a Design Pattern?

- A standard, reusable solution to a commonly occurring software design problem.
- A pattern is a **concept**, not a ready-made implementation.

## Why Learn Design Patterns?

- They provide a **common language** between developers (e.g., "Let's use Strategy here").
- You do **not** need to know every design pattern.
- Focus on understanding the **problem** each pattern solves, not just memorizing its implementation.

## Classification

| Type | Focus |
|------|-------|
| Creational | How objects are created |
| Structural | How objects and classes are structured and related |
| Behavioral | How objects communicate and distribute responsibilities |

## Features of a Good Design

- **Code Reusability**: The ability to reuse code in different parts of a system or even in other projects.
- **Extensibility**: The ability to add or change behavior with minimal modification to existing code.
